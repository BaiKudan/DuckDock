## Implemented contract

- `PackImport` retains backward-compatible `SINGLE_PUT` and adds
  `MULTIPART`, opaque upload ID, bounded part size and completion time.
- Multipart resume reads part number, ETag and size from MinIO. Completion
  requires sorted contiguous receipts, an exact part count, exact part sizes,
  expected total size and the existing whole-Pack SHA-256/preflight path.
- `PackBatchStream` and immutable `PackBatchReceipt` bind one
  ReporterCredential/stream to sequence, item idempotency key and canonical
  request SHA. Out-of-order receipts persist without crossing a gap;
  retryable dependency errors create no receipt.
- A batch acknowledgement covers durable import-session initialization.
  Producers must retain Pack bytes in their upload state until the Pack reaches
  `IMPORTED`/`IMPORTED_PARTIAL` or a permanent rejection; advancing this
  initialization cursor is not authorization to discard the Pack.
- `PackExport` creates one idempotent, immutable `duckdock-pack/1.0` object
  from existing Run trajectory artifacts. Source bytes are re-read and checked
  against Artifact size/SHA, ATIF version, metadata-only policy and Secret
  Canary before export.
- Evaluation replay re-reads and verifies the immutable `EVALUATION` object,
  then creates one idempotent, low-sensitive
  `EvaluationResultReplayed` Outbox event. It does not rerun an evaluator or
  introduce the Dataset/Evaluator/Evaluation domain deferred to NEXT-004.
- Pack capability negotiation remains backward compatible:
  `artifact_import + partial_loss` is `DD-C1+ARTIFACT`; DD-C3 is negotiated
  only when the client also declares `atif_export`, `resumable_upload`,
  `durable_batch_ack`, `evaluation_replay` and
  `otel_trace_correlation`, and artifact storage is available.
