# 01. 产品 PRD

## 1. 产品名称

DuckDock Enterprise Agent Control Plane

中文名称：DuckDock 企业 AI Agent 资产与交接控制平面。

## 2. 背景

DuckDock 现有能力以企业私有 Skills 仓库为核心，已经具备 Namespace、Skill 版本、发布门禁、Scanner、Sandbox、ReleaseGate、Clinic、Langfuse、Webhook、Robot Token、审计、IAM 等基础能力。

随着企业实际使用 AI Agent 平台，问题已经从“如何管理 Skill 包”升级为：

- 谁创建了什么 AI 能力。
- 这些能力在哪些运行时、项目、客户环境里被使用。
- 它们产生了哪些工作历程、文件、会话和执行结果。
- 员工离职、项目交接、外包团队撤场时，企业如何安全接管。
- 多厂商平台之间如何统一资产口径和治理流程。

因此 DuckDock 应升级为企业 AI Agent 资产与交接控制平面。Skill 仓库只是资产类型之一，真正的商业价值是把 AI 能力、运行现场、工作历程、权限凭证、交接审批统一治理。

## 3. 产品定位

DuckDock 是企业 AI Agent 资产控制平面；专有 OpenClaw 是它的智能采集、理解和执行探针。

DuckDock 负责：

- 企业级 AI 资产目录。
- 资产归属、运行绑定、工作历程、证据链。
- 离职和项目交接工作流。
- 审批、审计、权限、策略、报表。
- 多平台 Adapter 数据标准化。

专有 OpenClaw 探针负责：

- 在授权范围内连接 OpenClaw、ArkClaw、WorkBuddy、JVS 和线下定制平台。
- 采集 Agent、Skill、Workflow、会话、文件、运行记录、任务、产物。
- 生成带证据的交接建议。
- 在审批通过后执行备份、导入、禁用、归档、权限转移等动作。

## 4. 产品目标

### 4.1 业务目标

- 降低员工离职导致 AI 能力、项目上下文、自动化任务丢失的风险。
- 帮助云计算和 AI 代理服务商统一管理多厂商 Agent 项目。
- 为客户提供“AI 资产盘点、接管、审计、复用”的可交付产品。
- 将 DuckDock 从 Skill 仓库升级为企业级控制平面，提高商业价值和客单价。

### 4.2 产品目标

- 建立统一 AI 资产模型，覆盖 Skill、Agent、Prompt、Workflow、MCP、知识库、运行任务、会话、产物、凭证引用。
- 建立工作历程模型，记录 AI Agent 的运行记录、输入输出摘要、产物、调用人、时间线和证据。
- 建立离职/项目交接流程，支持发现、分析、建议、审批、执行、验收、归档。
- 建立跨厂商 Adapter 框架，第一阶段支持 OpenClaw 和 JVS，第二阶段支持 ArkClaw，第三阶段支持 WorkBuddy。

## 5. 目标用户

| 角色 | 诉求 |
|---|---|
| 企业 CTO / CIO | 看到企业 AI 能力资产、风险和使用价值，避免资产黑盒 |
| AI 平台管理员 | 管理多厂商 Agent 运行时、权限、资产目录、接管流程 |
| 项目经理 | 知道项目中哪些 AI 能力可复用、谁负责、交接状态如何 |
| HR / 行政交接负责人 | 员工离职时触发 AI 资产交接，不遗漏关键能力 |
| 安全与合规负责人 | 审计谁访问了什么、谁转移了什么、凭证是否轮换 |
| 一线开发/交付人员 | 能看到自己名下企业 AI 资产，主动移交和认领 |
| 代理服务商交付团队 | 用统一平台托管火山、腾讯、阿里、OpenClaw 定制项目 |

## 6. 核心场景

### 6.1 员工离职交接

1. HR 或管理员在 DuckDock 创建离职交接事件。
2. DuckDock 根据员工账号、邮箱、平台身份映射找到关联运行时。
3. 专有 OpenClaw 探针采集该员工相关 AI 资产和工作历程。
4. DuckDock 生成交接包和风险报告。
5. 直属主管、接收人、安全管理员审批。
6. 审批通过后执行归属转移、权限回收、凭证轮换、任务改派。
7. 接收人确认验收，系统归档证据链。

### 6.2 项目交付/撤场

1. 交付团队选择客户、项目、平台实例。
2. 探针采集项目下所有 Agent、Skill、Workflow、定时任务、知识库和文件。
3. DuckDock 输出项目 AI 资产清单、维护人、运行时绑定、风险项。
4. 交付结束时生成项目接管包。
5. 客户或内部运维团队完成接收。

### 6.3 多厂商资产盘点

1. 管理员配置 OpenClaw/JVS/ArkClaw/WorkBuddy 连接器。
2. 系统定时同步各平台资产。
3. 统一映射到 DuckDock AIAsset、WorkTrace、RuntimeBinding、Evidence。
4. 仪表盘展示按平台、部门、项目、人员、风险等级聚合的数据。

### 6.4 Skill 仓库治理

1. 用户在 DuckDock 创建或发布 Skill。
2. Scanner、Sandbox、ReleaseGate、Clinic 继续作为质量门禁。
3. Skill 同时作为 AIAsset 类型进入统一资产目录。
4. 当 Skill 被外部平台引用时，建立 RuntimeBinding。

## 7. 功能范围

### 7.1 P0 必须交付

- 统一 AI 资产目录。
- 人员、组织、项目、客户、运行时实例管理。
- OpenClaw Adapter：基于 Gateway API 和 backup 包的采集。
- JVS Adapter：基于公开 API 的逻辑接管包。
- 离职交接工作流。
- 交接包生成、审批、执行结果留痕。
- 工作历程摘要和产物索引。
- 审计日志和证据链。
- 前端资产中心、交接中心、运行时中心、风险中心。

### 7.2 P1 应交付

- ArkClaw Adapter：对接备份/恢复能力和安全日志。
- WorkBuddy Adapter：企业后台/API 优先，必要时使用浏览器自动化采集。
- 凭证引用识别和轮换工单。
- 资产血缘图谱。
- 高级报表：复用率、无人维护资产、离职风险、平台资产分布。
- 交接策略模板。

### 7.3 P2 可延后

- 自动生成交接说明书。
- 跨平台迁移执行。
- AI 风险评分模型训练。
- 插件市场和第三方 Adapter SDK。
- 多租户 SaaS 商业化计费。

## 8. 非目标

- 不做员工桌面监控。
- 不采集个人私人浏览器、私人聊天、私人文件。
- 不绕过厂商平台权限模型。
- 不在未审批场景下直接查看或导出完整敏感会话内容。
- 不把 LLM 判断直接作为最终事实，必须保留证据和人工复核。

## 9. 成功指标

| 指标 | MVP 目标 |
|---|---|
| OpenClaw/JVS 资产同步成功率 | 大于 95% |
| 离职交接包生成时间 | 小于 30 分钟 |
| 关键资产遗漏率 | 通过人工抽检低于 5% |
| 审批动作审计覆盖率 | 100% |
| 接管动作可回放率 | 100% |
| 员工可见资产确认率 | 大于 80% |
| 平均交接周期 | 比人工方式降低 50% |

## 10. 隐私与员工体验原则

- 产品表达使用“资产盘点”“项目交接”“企业能力目录”，避免“监控”叙事。
- 员工可以查看自己名下企业 AI 资产。
- 默认采集元数据、摘要、产物索引，不默认暴露完整敏感内容。
- 管理员查看敏感内容必须有权限、原因、审批和审计。
- LLM 生成的是建议，不是最终处置结果。
