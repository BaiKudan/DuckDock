# 05. 前端 PRD

## 1. 前端定位

前端是企业 AI Agent 资产控制台，面向平台管理员、项目经理、HR、安全负责人和交付团队。设计目标是清晰、密集、可扫描、适合长期运维，不做营销型页面。

## 2. 技术方案

- React 18
- Vite
- TypeScript
- React Router
- TanStack Query
- Zustand
- Ant Design 5
- Ant Design Pro Components
- ECharts 或 Recharts
- lucide-react 用于补充图标

建议新增依赖：

```json
{
  "@ant-design/icons": "^5.x",
  "antd": "^5.x",
  "@ant-design/pro-components": "^2.x",
  "@tanstack/react-query": "^5.x",
  "echarts": "^5.x",
  "echarts-for-react": "^3.x"
}
```

## 4. 页面清单

### 4.1 首页仪表盘

组件：

- KPI 卡片：资产总数、活跃运行时、待交接资产、关键风险、待审批数。
- 平台分布图：OpenClaw、ArkClaw、WorkBuddy、JVS、Custom。
- 风险趋势图。
- 最近交接单表格。
- 最近采集任务表格。

使用 Ant Design：

- `Card`
- `Statistic`
- `ProTable`
- `Tabs`
- `Alert`

### 4.2 资产中心

- 资产名称。
- 类型。
- 来源平台。
- 所属运行时。
- 主负责人。
- 项目/部门。
- 状态。
- 关键等级。
- 最近使用时间。
- 风险标签。

交互：

- 多条件筛选。
- 保存视图。
- 批量认领。
- 批量加入交接单。
- 导出 CSV。

资产详情页 Tabs：

- 概览。
- 归属关系。
- 运行时绑定。
- 工作历程。
- 产物。
- 风险。
- 证据。
- 审计。

### 4.3 交接中心

交接单列表字段：

- 标题。
- 类型。
- 离职员工/项目。
- 接收人。
- 状态。
- 风险等级。
- 资产数。
- 截止时间。
- 当前审批人。

创建交接单流程：

1. 选择交接类型。
2. 选择离职员工或项目。
3. 选择运行时范围。
4. 配置采集范围。
5. 选择接收人与审批链。
6. 确认并启动采集。

交接单详情布局：

- 顶部状态条：Draft、Collecting、Analyzing、Pending Approval、Executing、Verifying、Completed。
- 左侧交接摘要。
- 中间交接项表格。
- 右侧风险和审批信息。
- 底部执行日志 Timeline。

交接项表格操作：

- 接受建议。
- 修改接收人。
- 标记人工复核。
- 跳过。
- 查看证据。

## 5. 前端状态管理

TanStack Query 负责：

- API 数据请求。
- 分页列表。
- 缓存。
- 重试。
- 乐观更新。

Zustand 负责：

- 当前租户。
- 当前用户。
- 权限缓存。
- UI 偏好。
- 全局筛选条件。

不要把服务端业务状态手写进 Zustand。

## 6. 权限体验

- 菜单按权限隐藏。
- 按钮按权限禁用并显示原因。
- 敏感内容必须二次确认。
- 审批操作必须展示影响范围。

## 7. 视觉与交互原则

- B 端控制台风格，避免大面积装饰和营销文案。
- 列表优先，详情抽屉辅助。
- 创建流程用 Steps。
- 证据和执行日志用 Timeline。
- 资产关系图可使用 ECharts graph。
- 所有表格必须支持搜索、筛选、排序、分页。
- 所有异步任务必须有进度状态和错误详情。

## 8. 前端验收标准

- 所有 P0 页面可通过路由直接访问。
- 刷新页面后上下文不丢失。
- 权限不足时不出现可执行入口。
- 表格 1 万条数据场景下分页可用。
- 创建交接单完整流程可走通。
- 审批、执行、查看证据均有明确反馈。
- TypeScript 无 `any` 滥用，核心 API 类型由 OpenAPI 生成。
